### 문제 → 가설 → 검증 → 결론 과정 기록

**1. MinIO 이미지를 받을 수 없음**

- #### 문제: Docker Hub `minio/minio`가 404. quay.io는 인증이 필요하고, 알려진 마지막 릴리스 태그도 매니페스트가 없었음.
- **가설 A**: 일시적 장애나 태그 오류 → 검증: 다른 태그와 레지스트리를 조회 → 기각 (공식 이미지가 더 이상 배포되지 않는 것으로 보임)
- **가설 B:** 프로젝트 자체의 배포 정책 변경 → 검증: 웹에서 확인 → 확인. MinIO 커뮤니티 에디션은 2025년 말부터 유지보수 모드이고 소스만 공개하며, 공식 바이너리와 컨테이너 이미지를 더 이상 내지 않는다는 글이 있음 (글 하나로 확인한 내용, 정확한 날짜는 미확인).
- 대안 비교: SeaweedFS(Apache 2.0, 2015년부터 프로덕션, 컨테이너 1개로 S3 제공), Garage(AGPL v3, 초기 설정 스크립트 필요), MinIO 소스 빌드(보안 패치를 직접 챙겨야 함), RustFS(문서에 프로덕션 사용 금지로 적힌 알파)
- 조치: **SeaweedFS 4.48 채택**. 세 프로젝트 모두 S3 호환이 100%는 아니라는 경고가 있어서, DuckDB로 Parquet 읽기(D08)와 DVC 원격(D18)을 쓸 수 있는지 **D01 통합 테스트에 미리 넣음** (버킷 생성, 객체 쓰기·읽기, DuckDB httpfs로 Parquet 읽기, 잘못된 키 403).
- 결론: SeaweedFS 4.48로 결정 후 이미지 설치 완료.

**2. SeaweedFS 텔레메트리와 컨테이너 종료**

- 문제: 기동 로그에서 데이터가 10GiB를 넘으면 외부로 통계를 보내게 되어 있음을 확인. 끄려고 넣은 `-telemetry=false`는 잘못된 플래그라 컨테이너가 바로 종료됨.
- 조치: `-master.telemetry=false`로 수정해서 해결 (수정 1회).
- 결론: 설정 옵션을 추가할 때는 이미지 안에서 실제로 받아들이는 플래그인지 확인해야 함.

**3. CI가 브랜치 push로는 돌지 않음**

- 문제: `feat/d01-skeleton`을 push했는데 CI 실행 기록이 0건.
- 원인: 워크플로가 `main` push와 `pull_request`에서만 실행되도록 되어 있었음.
- 조치: PR을 만들어서 CI가 실행되게 함. 통과 확인 후 병합.

**4. 환경 설정 중 막힌 두 가지 (작업 전)**

- `claude: command not found`: 설치는 됐는데 경로 문제로 보임 -> 홈 디렉토리로 cd해서 `claude --version` 명령어로 다시 설치 확인된거 체크함.
- SSH `Permission denied (publickey)`: 키 생성과 로컬 지문은 정상이었고, 공개키를 GitHub에 등록하지 않아서였음. 등록 후 `Hi sjb2277!`로 인증 성공.
