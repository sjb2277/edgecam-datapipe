# Week 1 · 기반과 링크 계층 (11/2 ~ 11/6)

주간 목표: 영상이 링크를 건너 수신 서버에 도착하고, 첫 이벤트 3종이 스키마 검증을 거쳐 버스에 들어간다.
결정 게이트 G1(D04): 링크 기본 모드 확정.
참고: 규칙은 루트 `CLAUDE.md`, 개요·스택·포트·데이터 계약은 `overview.md`.

### D01 · 11/2(월) · Repo 골격과 core 인프라

- 작업
  1. repo 구조 생성(`CLAUDE.md`의 레포 구조 참고), uv 프로젝트(Python 3.11), ruff·pytest·pre-commit 설정. pytest는 단위/통합(`@pytest.mark.integration`)을 분리하고 `make test`는 단위만 실행
  2. Makefile 기본 타깃: `make up PROFILE=core`, `make down`, `make test`, `make lint`, `make schemas`(D05에서 구현)
  3. GitHub Actions CI: lint + 단위 테스트
  4. `docker/compose.yaml`의 `core` 프로파일: Redpanda(`--smp 1 --memory 1G --overprovisioned`, 기동 실패 시 `--reserve-memory 0M` 검토 후 보고), Redpanda Console, Postgres+TimescaleDB, MinIO
     - Redpanda는 `internal://0.0.0.0:9092`, `external://0.0.0.0:19092` 두 리스너를 쓰고, advertise 주소는 internal `redpanda:9092`, external `localhost:19092`
     - Schema Registry는 internal 8081, external 18081
     - 이미지 태그를 확정해 고정(latest 금지), 포트·자격 증명은 `.env`에서 주입하고 `.env.example`만 커밋
  5. `docker stats`로 유휴 메모리 실측
- 완료 기준: `make up PROFILE=core` 후 서비스 4개 healthy, 호스트에서 `localhost:19092`, `localhost:18081` 접속 확인, CI 녹색
- 기록: 실측 메모리 표, ADR-0001 메시지 버스 선택, 호스트 포트 최종 배정

### D02 · 11/3(화) · 카메라 캡처와 프레임 송수신

- 작업
  1. GStreamer로 `/dev/video0` 캡처, 640x480 고정(Week 0 확인값 기준 fps)
  2. H.264(`x264enc tune=zerolatency`) RTP/UDP 송신, 수신 측 디코드
  3. 송신 시 RTP 타임스탬프·capture_ts 기록, 수신 시 recv_ts 기록
  4. RTP 타임스탬프 기준 송수신 매칭 스크립트
- 완료 기준: 60초 송수신에서 매칭률, 평균·p95 지연 출력
- 기록: ADR-0002 프레임 식별 방식(RTP ts 매칭 vs 스트림 내 seq 삽입)

### D03 · 11/4(수) · 링크 계층 A: netns + netem

- 작업
  1. `ip netns`로 `ue`, `edge` 네임스페이스 생성, veth 페어 연결
  2. 송신 agent는 `ue`, 수신 서버는 `edge`에서 실행
  3. `scenarios/*.yaml`(delay, jitter, loss, rate) → `tc qdisc netem` 명령 변환기
  4. 시나리오 적용값을 `link.metrics` 형식으로 기록하는 어댑터
- 완료 기준: 시나리오 3개(정상, 지연, 손실)에서 수신 fps와 지연 변화 확인
- 기록: 시나리오 정의 방식, netns 구성도
- 주의: ip netns, tc는 sudo가 필요하므로 계획에 명시해 승인받는다.

### D04 · 11/5(목) · 링크 계층 B: OAI rfsim 검증 (게이트 G1)

- 작업
  1. CN5G(docker) + gNB + nrUE rfsim 기동, 작은 대역폭(PRB) 설정부터
  2. UE 터널 인터페이스로 ping, iperf3, 이어서 영상 RTP 송출
  3. CPU·RAM 실측, gNB 통계 로그에서 추출 가능한 지표 목록화
  4. 같은 `link.metrics` 스키마로 내보내는 rfsim 어댑터 초안
- 완료 기준: 아래 중 하나로 결정
  - A: 영상 송출이 안정적 → rfsim을 "검증 모드"로 채택
  - B: CPU 포화나 연결 끊김 → netem 단일 모드, rfsim은 W4에 시연 run 1회만
- 기록: ADR-0003 링크 기본 모드, 실측 자원표

### D05 · 11/6(금) · 첫 이벤트를 버스로

- 작업
  1. 이벤트 모델: `EventBase`(envelope 6필드)를 정의하고 `FrameSent`, `FrameRecv`, `LinkMetrics`가 **상속**한다(중첩 금지). 모델마다 `title`을 둔다. `make schemas`로 `schemas/*.json` 생성
  2. 스키마 등록 스크립트 `pipe schema register`: subject `<topic>-value`, 호환성 BACKWARD 설정. 등록 전에 생성된 스키마에 `$ref`/`$defs`가 있는지 점검하고 있으면 보고한다
  3. 호환성 실험: 같은 subject에 선택 필드를 추가한 두 번째 버전을 등록해 실제 Redpanda 이미지에서 호환성 검사가 동작하는지 확인하고 결과를 기록한다(문서가 버전별로 다르게 설명하는 부분)
  4. `common/producer.py`: confluent-kafka Producer + JSONSerializer. `auto.register.schemas=False`, 페이로드 검증(`validate`) 활성. 검증 실패 시 예외로 중단하지 않고 `<topic>.dlq`에 `{original_payload, error, source_topic, failed_at, stage}` JSON 문자열 전송
  5. `frame.sent`, `frame.recv`, `link.metrics` 발행
  6. run 관리 CLI: `pipe run start --scenario <name>` → `meta.runs` 기록, `pipe run stop`
  7. 테스트: 단위(브로커 mock으로 DLQ 라우팅·envelope 검증)와 통합(`@pytest.mark.integration`, 실제 브로커) 분리
- 완료 기준: Console에서 토픽 3개 메시지와 DLQ 샘플 확인, 단위 테스트 통과, 통합 테스트 1개 이상 통과, 호환성 실험 결과 기록
- 기록: envelope를 상속으로 설계한 이유, 레지스트리 호환성 실험 결과, DLQ 형식
