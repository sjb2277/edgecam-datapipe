# Week 2 · 수집과 저장 (11/9 ~ 11/13)

주간 목표: 모든 이벤트가 Hot과 Cold 양쪽에 손실·중복 없이 쌓이고, 장애가 나도 복구된다.
결정 게이트 G2(D10): 장애 주입에서 최종 테이블 손실 0을 확인하기 전에는 W3로 넘어가지 않는다.
참고: 규칙은 루트 `CLAUDE.md`, 개요·스택·포트·데이터 계약은 `overview.md`.

### D06 · 11/9(월) · 엣지 추론

- 작업
  1. YOLO11n → OpenVINO export, `intel:cpu`와 `intel:gpu` 추론 지연 비교
  2. 수신 프레임 추론 → `inference.detections` 발행(D05의 Producer 사용, 스키마 등록 포함)
  3. 원본 프레임 정답 비교는 실시간으로 하지 않고 배치로 미룬다(샘플 프레임 저장 후 D13에서 reference 추론)
- 완료 기준: 디바이스별 infer_ms 분포, 처리 fps 기록
- 기록: ADR-0004 추론 디바이스와 reference 방식

### D07 · 11/10(화) · Hot path: stream-loader

- 작업
  1. confluent-kafka consumer → TimescaleDB `bronze.*` 하이퍼테이블에 배치 적재(COPY)
  2. insert 성공 후 offset 커밋 → at-least-once 보장
  3. `event_id` PK + `ON CONFLICT DO NOTHING` → 중복 재전송 무해화
  4. 역직렬화·검증에 실패한 메시지는 DLQ(`stage: loader`)로 보내고 offset은 커밋한다
  5. 토픽 메시지 수와 bronze 행 수를 비교하는 검증 스크립트
- 완료 기준: 10분 실행 후 건수 일치, 적재 지연 p95 측정
- 기록: 전달 보장 수준을 at-least-once + 멱등으로 정한 이유

### D08 · 11/11(수) · Cold path: archiver

- 작업
  1. consumer → 시간·건수 기준 micro-batch → pyarrow Parquet → SeaweedFS S3 `raw/source=/run_id=/`
  2. 원본 프레임 JPEG 샘플 저장 정책 구현(예: 1초 1장 + 열화 구간 전량)
  3. DuckDB로 SeaweedFS S3 Parquet 직접 조회
- 완료 기준: Cold 건수 = Hot 건수, 파티션 구조 확인
- 기록: ADR-0005 프레임 샘플링 정책(전량 저장을 제친 이유: 용량 계산 포함)

### D09 · 11/12(목) · 프로브와 장비 텔레메트리

- 작업
  1. `net.probe`: ping 기반 rtt·jitter·loss 1초 발행
  2. ESP32 펌웨어 v0: 거리, 서보 각도, LED 상태를 JSON line으로 시리얼 출력
  3. device-gateway: 시리얼 읽기 → `device.telemetry` 발행 (부품 미도착 시 시뮬 장치로 대체, 스키마 동일)
- 완료 기준: 6종 중 5종 토픽이 Hot·Cold에 적재(`control.*` 제외)
- 기록: 배선도 사진, 시리얼 프레이밍 방식
