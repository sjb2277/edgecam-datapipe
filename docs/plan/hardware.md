# 하드웨어 구성

ESP32 1개, 서보 2개, 초음파 센서 1개, LED와 부저면 충분하다. 대부분 동아리방 상비 부품이라 먼저 빌리고, 없는 것만 산다.

## 연결 방식

장비는 "제어 대상"이면서 동시에 "6번째 데이터 소스"다. 연결은 게이트웨이 패턴으로 한다.

```text
ESP32 ↔ USB 시리얼 ↔ device-gateway(UE 쪽) ↔ 링크 ↔ 엣지 컨트롤러
```

- 장비 데이터도 링크를 건너므로 링크 열화가 제어 지연에 미치는 영향까지 측정된다.
- 학교 Wi-Fi는 기기 등록 문제가 생길 수 있어 시리얼을 기본으로 한다. MQTT over Wi-Fi는 선택 확장이다.
- 시리얼 프레이밍은 JSON line(한 줄 = 메시지 1개)으로 한다. 펌웨어는 PlatformIO(C++)로 작성한다.

## 부품 목록

| 부품 | 수량 | 용도 | 비고 |
| --- | --- | --- | --- |
| ESP32 DevKit (ESP32-WROOM-32) | 1 | 센서 읽기, 액추에이터 구동, 시리얼 통신 | 필수 |
| SG90 마이크로 서보 | 2 | 팬틸트 포인터 방향 제어 | 필수 |
| 팬틸트 브래킷 | 1 | 서보 2개 고정 | 없으면 서보 1개로 축소 |
| HC-SR04 초음파 센서 | 1 | 거리 텔레메트리, 폐루프 조건 | 에코 핀 5V라 분압 저항 필요, 3.3V 호환 모델이면 불필요 |
| LED(빨강, 초록) + 220Ω | 각 1 | 상태 표시 | 필수 |
| 액티브 부저 | 1 | 경보 | 선택 |
| 저항 1kΩ, 2kΩ | 각 1 | 초음파 에코 분압 | 필수 |
| 브레드보드, 점퍼선(M-M, M-F) | 1세트 | 배선 | 필수 |
| 데이터 지원 USB 케이블 | 1 | 시리얼 통신, 펌웨어 업로드 | 충전 전용 케이블 주의 |
| 외부 5V 전원 | 1 | 서보 2개 동시 구동 시 전류 보강 | 서보가 떨리면 추가 |

## 조달

- 구매가 필요해도 대부분 저가 부품이라 전부 사도 수만 원 안쪽일 것으로 보이지만, 가격은 확인하지 않았다.
- Week 0에 동아리방·연구실 재고를 확인하고, 부족한 부품은 W2 D09 전에 도착하도록 11/2(월)에 주문한다.
- 도착 전에는 같은 스키마(`device.telemetry`)를 내는 시뮬레이션 장치로 개발한다(`src/pipe/gateway/`의 가상 장치 모드).

## 폐루프 시나리오 (W5)

1. 사람 검출 + 초음파 거리 임계값 이하 → LED 빨강, 부저 경보
2. 검출 bbox 중심 좌표 → 서보 각도로 포인터 추적 (일정이 밀리면 가장 먼저 줄인다)
3. 링크 상태가 "열화"로 판정 → V4L2로 카메라 해상도·fps 하향 (소프트웨어 제어)
